# ASCII by Star: notes for Claude

Photoshop UXP plugin (manifest v5, id `com.ostap.asciibystar`, PS ≥ 25). The user tests in Photoshop 2026 (v27.11) on macOS and on Windows 11; changes must work on both. The glyph atlas can only be rebuilt on macOS (`gen_atlas.swift` needs Menlo), so on Windows don't change `charsets.js` in a way that needs new glyphs.

- `plugin/engine.js` is pure JS and shared by the plugin and the Node tools. Keep it free of Photoshop APIs.
- UXP canvas can't draw text, so glyphs come from `plugin/atlas.bin`: 8-bit alpha, 24×47 cells of Menlo at 40pt, rasterized by `tools/gen_atlas.swift`. Rebuild it after changing `charsets.js`.
- Modules load via `require("./x.js")` from `main.js`. Do not add `<script>` tags for them.
- Output layers are named `<source layer> ASCII by Star` (`OUR_RE`; older `#xxxxxx` tags still recognised). Re-edit settings live in localStorage under `gf:layer:<doc title>:<layer id>`, with `gf:layerName:<name>` as a fallback. Merged reads hide these layers first.
- Composite `imaging.getPixels` fails on some documents ("Could not update smart object files"), e.g. artboards. `readViaStamp()` falls back to a temporary mergeVisible layer.
- The UXP text API (`createTextLayer`, leading) takes pixel values, not points.
- Icons: the manifest path `icons/x.png` with `scale: [1,2]` means the files must be named `x@1x.png` and `x@2x.png`. Generate them with `node tools/make_logo.js`.
- Font list: use batchPlay `get fontList`. Walking `app.fonts` takes about 30 s.
- Build and install: `node tools/package.js --install` (macOS and Windows: its own zip writer, then Adobe's UnifiedPluginInstallerAgent; `tools/package.sh` just runs it). On Windows the agent exits 0 without installing, so the script checks `%APPDATA%\Adobe\UXP\PluginsInfo\v1\PS.json` and otherwise opens the .ccx in Creative Cloud, which asks twice (Replace current version ▸ Continue, then the third-party warning ▸ OK) and reloads the panel without a Photoshop restart. On Windows run a test .psjs with `Photoshop.exe <path>` while Photoshop is open, and keep `LOG_MIRROR` short (e.g. `%TEMP%\asb-test\x.log`): Photoshop silently fails to save the test PNGs to paths over 260 characters, such as the scratchpad. Headless Photoshop tests: `node tools/build_test.js`, then `open -a "Adobe Photoshop 2026" test/gf_test.psjs`. The log lands in the UXP PluginData temp folder. A syntax error in a .psjs leaves a dialog open in Photoshop that blocks later scripts.
- No screen or accessibility access from the shell. Ask the user for screenshots of the panel.
- Glitch: three stages in engine.js. `glitchSource` runs on the analysis image, `glitchGrid` on the character grid, and `glitchOutput` on the rendered RGBA (row-local only, so strip rendering matches). Everything is gated by `s.glitchOn` and seeded by `s.glitchSeed`, with sizes in document-relative units. Never add an effect that moves pixels vertically in `glitchOutput`.
- Before shipping engine changes: render all looks with `node tools/test_engine.js test/sample.png <dir>` and compare md5s with the previous build (unrelated looks must be byte-identical). Then `node tools/ui_smoke.js`: it checks that every element id main.js uses exists in index.html and that the UI builds. The "no atlas" error is expected.
- Live view = smart object: `toggleLive` places a smart object (`placeSmartObject`), selects it, runs `placedLayerEditContents` and treats the opened .psb as the live window. `runLive` writes into it (with corner markers), and `saveLive` saves the .psb about 0.9 s after edits pause, which updates the parent. `closeLive` saves and closes. In-panel zoom/pan was removed because UXP routes wheel events badly.
- Apply quality > 1: `placeSmartObject` renders N× into a scratch doc (with invisible corner pixels so bounds equal the canvas), runs `newPlacedLayer`, duplicates into the source doc and scales by 1/N anchored top-left. If it fails it falls back to a pixel layer and says so in the status line.
- Custom fonts: `buildFontAtlas` creates one text layer per character in a scratch doc, reads the composite and crops the glyphs centred into cells. Results are cached in memory and in the data folder as `font-<hash>.json/.bin`. `readyAtlas()` must run before any render; it swaps the global `atlas`. Cache keys include `atlas.id`.
- Installing: Adobe's installer keeps old versions enabled side by side, and Photoshop may load an old one. `tools/package.js --install` removes every copy first. Check `~/Library/Application Support/Adobe/UXP/PluginsInfo/*/PS.json` if the user doesn't see a change.

- Ink bleed tab: `plugin/ink.js` is the effect (pure JS, like engine.js) and `plugin/inkui.js` holds the tab's UI and Photoshop I/O. It writes a group "<source> Ink Bleed" above the source with the layers Ink bleed and Ink pooling (Multiply), Ink gaps (Normal) and Paper (Multiply). Multiply and Screen swap for light ink on dark. Ink gaps are painted with what's under the source (`readUnder`: source and the group hidden for the read), so they reveal the real paper. Without that read they use the detected paper colour. Never hard-code white or black here: assuming black paper for light ink caused "black dots" on white text over blue. Everything is computed in "dark space", where light sources are inverted on the way in and out. Sizes are px on a 3000 px long side (`Ink.REF`). Randomness is hashed from world coordinates, and wide blurs run on a power-of-two grid aligned to world coordinates, so tiles and previews match exactly. Check with `node tools/test_ink.js <png> <dir> [--ascii presetId --long 2400 --size 44] --check` (expect "max tile difference 0.0"). Photoshop steps: `TEST=ink node tools/build_test.js`.
- `imaging.getPixels` with `targetSize` reports `sourceBounds` in a downscaled pyramid level, not in document px. `inkui.readRect` clips the request to the layer bounds itself and ignores the returned bounds.
- Photoshop 27: `imaging.getPixels` with `componentSize: 8` on a 16- or 32-bit document fails with "Could not create a new document". Always read at native depth and convert with `toRGBA8`. New documents inherit the user's last bit depth, so scratch and test documents pass `depth: 8` explicitly.
- Test logs: the Photoshop temp folder that holds the log is privacy-protected from the shell. Build with `LOG_MIRROR=<path in the scratchpad> node tools/build_test.js` and the log (plus any test PNGs) is mirrored next to that path.
- Keep transparency (`keepAlpha`, default on): the solid background is masked by per-cell source coverage, interpolated between cell centres. Fully opaque sources take the old code path, so their output is byte-identical.
- Panel input: checkboxes go through `onCheck` (UXP may not send "change" for clicks on the label). Sliders are drawn by `plugin/slider.js` (`makeSlider` + `SLIDER_HTML`, pointer events with a mouse fallback), because native range inputs on macOS take mouse-wheel events while hovered. Don't go back to `<input type=range>`. Text fields and checkboxes work the same way (`plugin/fields.js`, `enhanceAllFields` before listeners are added): native ones trail behind the rows while the panel scrolls. The real `<input>`/`<textarea>` stays hidden as the source of truth and swaps in only while typing; call `refreshFields()` after setting values in code. Dropdowns work the same way: `plugin/dropdown.js` hides each `<select>` (it stays the source of truth for value, options and "change") and draws a button plus a list that opens below the row. `enhanceAllSelects` must run before any "change" listener is added. To click through the real panel in a browser, serve index.html with stubs for `require("photoshop"/"uxp")`.
- Ink textures: a picked image file goes on a recent list (`gf:inkTextures`, with a persistent token). Photoshop opens it once, converts it to RGB, flattens it if needed and reads it at ≤3072 px. The pixels are cached as `tex-<id>.bin/.json` in the data folder, and the id hashes path, size and date, so an edited file reloads. `Ink.prepareTexture` builds a mip pyramid of the colour plus a high-passed luminance "height" that replaces the generated grain. `placeTexture` covers the canvas at scale 1, mirror-tiles below that, and rotates 90° to match orientation. A texture whose brightness doesn't match the paper (dark noise scan under dark ink) is inverted, and the paper layer always multiplies on light paper and screens on dark.
- Shadows (drop, long, offset, glow): `renderWithShadows` in engine.js. It renders the characters alone over the view grown by the shadows' reach, builds each shadow from their coverage (shift, blur, or a one-pass extrude sweep for the long shadow), and stacks background (`_noGlyphs` render), shadows, then characters. glitchOutput runs last. Sizes are fractions of the font size; `shadowAngle` uses Photoshop's light-angle convention. Strips must match a one-piece render exactly (diff 0). Photoshop steps: `TEST=shadow node tools/build_test.js`. With all shadows off, render takes the old path and the looks stay byte-identical.
- Custom text (`charset: "custom"`): `textMode` ramp (one character per brightness step), words (space-separated words ranked by ink, each with an equal share of the tones, greedy left to right) or phrase (the text written out in reading order; light cells are empty, `phraseShade` sets a per-cell glyph opacity `grid.shade`). Characters the built-in atlas lacks switch the atlas to Menlo rendered by Photoshop (`effectiveFont`), so nothing is dropped. Photoshop steps: `TEST=text node tools/build_test.js`. The test sets `baseAtlas` itself because init() doesn't run there.
- Ink look (settings version 2): the visible paper is `felt()` (dense short fibres, both lighter and darker than the paper) plus formation and speckle noise, centred on the paper colour. The bleed is `propagateFuel`: a geodesic sweep where ink spends fuel crossing the paper (fibres are cheap, `wicking` makes the long fibres cheaper), density fades with the fuel left, and the margin covers 5× `inkReach`. Bump `Ink.SETTINGS_VERSION` when the look changes; inkui then refreshes saved slider values from the paper type.
- Layout: `#previewWrap`/`#inkPreviewWrap` get a fixed height from `fitLayout`, and the status lines are a fixed height. A preview image swap (no size while loading) or a wrapping status must not resize the top area, or the settings list jumps while you drag a slider. `fitLayout` only writes styles that changed. Both previews use `plugin/viewer.js` (`createViewer`). It provides a zoom slider (Fit to 400%, logarithmic; the image scales instantly and re-renders once the slider rests), drag to move, and in Fit a click zooms to 100%. The tab only supplies `render(rect, z)`: a document rect to RGB at scale z. When zoomed, the viewer renders the visible area, then 3 × 3 views around it, and only renders again on refresh() or at the edge of what's rendered. To test it in a browser, serve a page with stubs for `require` and a canvas-based `imaging.encodeImageData`. The viewer also owns the preview height (`layout(H)`, called by `fitLayout`; a share of the panel set with the grip under the preview) and the Hide toggle in the zoom bar; while hidden, `refresh()` renders nothing until it's shown. Both are stored per tab (`<storeKey>:size`, `:hidden`). `trackDrag` in slider.js is the one pointer/mouse drag helper (sliders, preview pan, grip).
- Background: `bgOpacity` (0 = characters only) scales the solid or mosaic background; `keepAlpha` ("Follow the image's shape") masks it by the source's coverage.
- Charset levels: `buildCharset(atlas, ramp, sortByDensity, {extra, spread})`. `extra` characters (outline, fill, hidden messages) come after the ramp: drawable, never picked by tone (`n` counts the ramp only). With `spread` (dither "none"), a density-sorted ramp whose lightest visible glyph is above `MAX_FIRST` (digits, letters, 01) is stretched down to it, so one glyph doesn't take every mid tone. Build charsets with `Engine.charsetParts`/`charsetOf`, never from `customChars` directly.
- Fonts by platform: `MONO_FONT` in main.js is Menlo-Regular on macOS and Consolas on Windows (no Menlo there). It's the fallback for characters the built-in atlas lacks and the font of editable text layers.
- Custom text syntax: `{message}` / `{message*N}` hides a message (`parseCustom`); `[A|B]` / `[?A|B]` is the fill (`parseFill`, items in order or at random seeded by `fillSeed`; one random item = its single characters; items longer than one character get a space between them). The rest is the ramp/words/phrase. `applyFill` runs right after selection: without other text it fills every inked cell and empties the rest, otherwise only cells with ink > `fillLevel`. Fill and rain glyphs come from `itemStream`. `hideMessages` places them after selection (seeded by `hideSeed`), marks `grid.hidden`; `s._markHidden` (preview only) tints them.
- Outline (`applyOutline`, after selection, before glitchGrid): shape = cells with ink > `outlineLevel`; Chebyshev distance bands give the stroke; "lines" picks `| / - \` from the signed-distance gradient. "Your text" uses the Custom text syntax: the stroke writes its text in reading order (`writeSeq`) or a `[ ]` fill; the inside (`outlineFill: "text"`, `writeCustom`) runs ramp/words through `selectGlyphs` with its own charset (`cs.atlas`) on tones stretched from `outlineLevel`..1, mapped back into cs, or writes a phrase; `[ ]` fills take tones above `fillLevel`; `{messages}` go through `hideMessages` with an `allow` mask (stroke or inside) and their own seed offset, adding to `grid.hidden`. Both outline text boxes wait for Apply text (or Enter), like Custom text. Old "chars"/"random" fills become phrase / `[?…]` in `migrateSettings`. `outlineOpacity`/`outlineFillOpacity` go through `grid.shade`; at 1 the output is byte-identical. Photoshop steps: `TEST=feature node tools/build_test.js`; rain and fill: `TEST=rain`.
- Matrix rain (`applyRain`, after hideMessages, before glitchGrid, gated by `rainOn`): "object" starts streams at the shape's lower edges (shape = cells with a visible glyph before the rain) and stops them at the next shape; "everywhere" runs lines of streams per column over the whole grid. The head is the lowest cell; the fade goes into `grid.shade` (created filled with 1 when missing, which renders the same as none). Characters: `cs.rain` from `charsetParts(s, presetChars, rainPresetChars)` (rain characters are charset extras). Everything is hashed from `rainSeed` and cell positions, so strips match. Text exports use per-cell colours when the rain is on (`perCellColor`), with the fade mixed into the background.
- Panel: controls whose id equals the setting go in `SELECTS`/`CHECKS`/`TEXTS` in main.js (bound and synced in loops). Checkbox rows are `.row > label` (flex, no checkbox margin) so they line up with the label column; options that depend on a checkbox sit in a `.sub` group. Randomize keeps the font and custom text, varies size around the pre-run size, and has an undo stack. Turning a shadow on with a colour too close to the background picks a visible one (`visibleShadow`).
- Artboards: `plugin/pixels.js` (shared by both tabs) has `frameOf(doc, layerId, pick)`. It returns the area to work on: the artboard holding the source layer (Artboard menu "auto"), a chosen artboard, or the whole canvas. Capture, the grid, writeLayer (`at` = frame corner), smart objects, text layers, the ink tiles and paper, and the preview all use the frame. Smart objects are positioned before scaling: scaling down averages away the 1/255 corner pins, after which bounds shrink to the content. The test builder rewrites every `require("./x.js")` to `__mods.x`; add new modules to its wrap list in dependency order.
- Runtime facts (probed in PS 27.11): no WebGL, WebGPU, Worker or OffscreenCanvas, so nothing runs on the GPU; WebAssembly exists. Plugin JS runs at Node speed, so `tools/test_engine.js` timings carry over. Pixel I/O is cheap (putPixels 4000² ≈ 0.36 s); a batchPlay call ≈ 1.7 ms, so avoid per-layer calls on the preview path (`listArtboards` asks all groups in one call and caches for 1 s; `forgetArtboards()` on Photoshop events).
- Live view: `closeLive` marks `live.closing` first; `runLive`, `scheduleLive` and the background save skip a closing view. Photoshop steps: `TEST=live node tools/build_test.js`. The ink suite needs a `tex_test.jpg` next to `LOG_MIRROR`.
- Edit symbols: `S.cellEdits` holds hand edits ({op: write|color|erase|restore, text, color, pts | rect}, positions as fractions of the frame at cell centres). `applyEdits` runs after rain, before glitchGrid; `charsetParts` adds written characters to `extra`. They belong to the picture: `applyPreset`/undo Randomize keep them, presets and batch drop them (`lookOnly`), Reset all clears them. Dragging (`tool.drag`) paints freehand, draws a line/rectangle/ellipse (`shapeCells`, Shift = even shape) or selects a box (`cellSel`, applied by `applySelection`; the marquee button selects too). The panel side (main.js `editor`, `editFromSelection`) uses `viewer.setEditor` (click/drag edits, Option/Alt-drag pans) and `viewer.setMarks` (cell outline). The tool's own settings are `gf:editTool`, not in S. Checks: `node tools/test_edits.js`, Photoshop steps `TEST=edit`.
- render rounds glyph and mosaic positions in document space and then moves them by the view's whole-pixel offset, so strips agree exactly (rounding after the move flipped .5 ties into 1 px tears at strip seams).
- Active selection: `imaging.putPixels` is clipped to a marquee left in the document, which masked the output (e.g. after "Select the Photoshop marquee area"). Every pixel write (`writeLayer`, the ink tiles) runs inside `withoutSelection(doc, fn)` (pixels.js): it saves the selection (`getSelection`, else its bounds), deselects, writes, and puts it back with `putSelection`. Photoshop steps: `TEST=selection` (not yet run in Photoshop).
- Custom text syntax is everywhere you type text: Custom text, both outline boxes, the rain's characters and Edit symbols ▸ write. `{msg*N}` in the rain and in edits goes through `hideInRuns` (a message runs along one rain stream, top to bottom, or along an edit's cells in drawing order); an edit's `[ ]` fill replaces its plain text. New text inputs should parse with `parseCustom` and add `own(parseCustom(text))` to the extras in `charsetParts`.
- Cell backgrounds (`cf*` settings, section "cells"): `drawCellFx` in engine.js draws an effect behind each cell from its colour (`cfFrom` glyph = `grid.color`, image = `grid.rgb`, shifted by `cfShade`): tile, gradient (`cfGradT`: shape linear/reflected/radial/diamond/angle at `cfAngle`, across each cell or the whole frame with `cfGradSpan`, then ping-pong repeats, midpoint bias, steps, reverse, optional middle colour; the old "glow" fill is migrated to a radial gradient), or bleed (cell colours × weight blurred on the grid with `blurField`, sampled bilinearly). Then per-cell glitch (5 kinds hashed from `cfSeed`), scanlines and grain. `render` with `cfOn` stacks background (`_noGlyphs`), the cell effects, then the characters (rendered transparent) and glitchOutput; `_cfDone` stops the recursion, and renderWithShadows renders its characters with `cfOn: false`, so shadows fall on the cells. Pixel positions come from whole output pixels (`ox`, `oy` rounded) so strips match. With `cfOn` off the looks are byte-identical.
- Separate layers (Layers ▸ "Separate layers in a group", `gf:applyLayers`, default one layer): `applyAsGroup` makes a group named like the single layer (so OUR_RE, re-edit and merged reads treat it as the output) with one layer per `Engine.layerParts`, bottom to top. With `s._parts`, computeGrid records `grid.part` (text/outline/hidden/rain/edits) by diffing glyph+colour after each stage; `Engine.renderPart` renders one part (cells with normal blend; their cfBlend becomes the layer's blend mode; shadows via `_shadowsOnly`; glitch = the glitched render where it differs from the clean one). Parts come from a grid computed with the glitch off. `ourOutput(layer)` walks up to the "… ASCII by Star" group, so a child layer is never the source and re-edit finds the group. Photoshop steps: `TEST=layers` (not yet run).
- Sliders: double-click the name, the value or the handle resets (`onDoubleClick` in slider.js counts two clicks within 0.4 s as well, since UXP may not send "dblclick"; `makeSlider(…, onReset)`).
- Source default is "Active layer".
- The layer below: colorMode "under", outlineColorFrom "under", rainColorMode "under", cfFrom "under" and edits with `color: "under"` colour cells from the visible image under the source layer (with the visible image as source: under the active layer). `capture` reads it when `needsUnder(S)` (`readBelow`: the anchor, `layersAbove` it and our outputs hidden, in a discarded history step) into `src.under`; computeGrid averages it per cell (`cellUnder`, `grid.under`; `underOf(grid)` falls back to the image's colours). In that mode on a transparent background dark counts as ink.
- Old settings: `Engine.migrateSettings(s)` is the one place that upgrades values saved by older versions (bayer → bayer4, outline "chars"/"random", cell "glow"). `freshSettings` runs every loaded setting through it, so the engine itself only handles current values. Add new migrations there.
- Shared Photoshop I/O lives in pixels.js: `throwawayStep(ctx, doc, fn, own)` (a history step that is discarded, for temporary changes), `readWithHidden(doc, layerId, hide, R, z)` (read with layers hidden, shown again after), `layersAbove(doc, layer)`, `hasAlpha(rgba)`, `selectionBounds(doc)` and `withoutSelection`. capture, the layer below, the live background and the Ink tab's preview and `readUnder` all use them; don't write suspend/hide/read/restore by hand again.
- Previews: `Engine.flattenForPreview(rgba, w, h, backdrop)` takes an optional RGBA backdrop between the characters and the checkerboard (the live view's layers below, from `underBackdrop`).
- Depth echo (`echo*` settings, section "depth"): `drawEcho` repeats chosen parts (outline stroke via `grid.outlineStroke`, rain, the image's characters; picked with `grid.part`, which computeGrid now also tracks when `echoOn`) as copies scaled by (1 + echoStep)^±k around a vanishing point (the parts' bounding-box centre or echoX/Y). A copy is just `render` with the view moved and scaled (`x: vp + (view.x − vp)/sk, scale: view.scale·sk`), so glyphs stay sharp and strips match. `render` with `echoOn` stacks background + cells (`_noGlyphs`), shadows (`renderPart("shadows")`), the echo, then the characters; `_echoDone` stops the recursion and `NO_FX` turns it off for parts. Separate layers get a "Depth echo" layer.
- Cell fill "depth" (nested outlines): `cfDepthCount` rectangles shrinking by (1 − cfDepthPull)^k inside each tile, line width `cfDepthWidth` of the half size, drifting towards the picture's centre by `cfDepthAim`, colour A → cfTo, alpha × (1 − cfDepthFade·t).
- Rain streams are written by one `rainWriter(grid, s, cs, o)` (a stream = its cells in the direction of motion, head last, -1 off the grid) and placed by `slotStreams` (spaced along a line: whole-image rain, ring rain) or `edgeStream` (leaving a shape's edge). Falling rain builds its lines with the angle; `rainDir` "out"/"in" builds them along `raysFrom` (rays from a centre: `rainCentre` shape middle or `rainCX/CY`, curved by `rainTwist`, starting at `rainHole`·R). Falling rain is pixel-identical to before this refactor; keep it so (compare against `git show HEAD:plugin/engine.js`).
- Outline outer ring (`outlineRing*`): the shape scaled by `outlineRingScale` around its bounding-box centre (`maskCentre`); `drawStroke` (shared with the outline, `maskDistance` for distances) strokes its edge, and the band between is filled with scattered custom text, text along rays, or rain along rays (`raysFrom` sized to the ring). The ring's rain has its own `rr…` settings: `RING_RAIN` maps each rain setting to its ring copy and `ringRainSettings(s)` puts them in the rain's places, so `rainWriter`/`slotStreams` draw it unchanged; its characters are `cs.ringRain` (`charsetParts(…, ringPresetChars)`), and "Copy from Matrix rain" copies through the same map. Ring text characters go into the charset extras. The ring and the band have their own opacity (`outlineRingOpacity`, `outlineRingFillOpacity`, through `grid.shade`), a band fade across its width (`outlineRingFade`, from the shape distance `dIn` and the ring distance), and colours (`outlineRingColorFrom`/`outlineRingTextColorFrom`: stroke | own | under | image, via `colorSetter`); `needsUnder` in main.js must list every "under" colour source.
- Text art tab (`plugin/textart.js`): FIGlet lettering like patorjk.com's TAAG, with the vendored figlet.js (`plugin/figlet.js`, the package's browser build, MIT) and its 332 fonts in `plugin/figlet-fonts/`. Fonts are read as bytes and decoded by `decodeFont`: strict UTF-8 (279, block and box characters; one has a BOM) or Latin-1 (53). UXP's utf8 reader throws on Latin-1 ("Failed to decode the given data with utf-8 encoding"); Node's doesn't, so test decoding with the bytes. `compose(T, render)` does the shaping after FIGlet (alignment and line gap per line, letter spacing letter by letter, case, trim, flip with character swaps, invert, draw with a character or text, frame); style presets save T without the text. Fonts are parsed on first use (`figlet.parseFont`); `textSync` takes the layouts ("default", "full", "fitted", "controlled smushing", "universal smushing"), `width` and `whitespaceBreak`. The preview renders the art through the engine in a plain look; "Try every font" renders small previews with the built-in atlas only. "Use with effects" sets `S.textArtOn/textArt/textArtFont`; then `capture` returns a pixel-less source (`textArtSource`, with the visible image as "the layer below") and computeGrid builds the grid from the art (`textArtAnalysis`: characters centred, inked cells = letters, gradient top to bottom; `textArtFit` sizes it to the area) before the usual pipeline (`finishGrid`). Text art and symbol edits are picture keys (`PICTURE_KEYS`): presets and Randomize leave them alone.
- New plugin files must be added to `FILES` in tools/package.js (it's an explicit list) and, if `main.js` requires them, to the wrap list in tools/build_test.js (in dependency order).
- Shared UI pieces: `picker.js` (`makePicker`: a button opening a search field and a paged list; the ASCII tab's font chooser and the Text art fonts) and `presetbox.js` (`makePresetBox`: built-in and saved presets with Reset, Save, Delete with "Sure?", Export/Import; the ASCII Look presets and the Text art styles). Use them for new choosers and preset lists. `history.js` (`makeHistory`) is the ↶ Undo for a tab's settings (ASCII: S and the saved looks; Text art: its T, including Randomize).
